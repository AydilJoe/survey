# Bulk Import Income from CSV

**Date:** 2026-05-02
**Status:** Design — approved by owner, awaiting implementation plan
**Owner:** AydilJoe
**Project:** Duitful (web app + Capacitor shell)

## 1. Goal & non-goals

### Goal

Let users bulk-add income entries (typically freelance gigs) from a CSV file in Duitful's existing 17-column export shape. Additive: existing income, expenses, debts, savings, and daily entries are not touched.

### Non-goals

- Per-transaction income data model. Each imported row maps to the existing monthly `state.income` shape (`{name, amount, month, day?}`). No new `daily-income` row type.
- Currency conversion. Amounts are taken at face value in the user's display currency.
- Smart aggregation. Three Upwork rows in April → three separate income lines, even if the `name` matches.
- Replacing the existing destructive `Import CSV` in Settings. That flow stays as the backup-restore path.
- Importing rows whose `type` is anything other than `income`. They are silently skipped (not counted as failures), so a user can drop a full export in and only the income rows land.
- Pro gating. Income is unrestricted today; bulk-add stays unrestricted.

## 2. CSV format accepted

Same 17-column shape as `toCSV()` in `app/script.js:2632`:

```
type,name,amount,balance,apr,minPayment,date,category,note,debtName,target,current,month,day,dueDay,kind,monthsLeft
```

For each row where `type === "income"`, the importer reads:

| Column | Required | Validation | Notes |
|---|---|---|---|
| `name` | yes | non-empty after trim | becomes the income line name |
| `amount` | yes | finite number, > 0 | RM (or whatever display currency) |
| `month` | no | regex `^\d{4}-\d{2}$` | falls back to current month if missing/invalid |
| `day` | no | integer 1–31 | optional; null otherwise |
| `note` | no | any text | folded into name as `"<name> — <note>"` (em dash with surrounding spaces) when non-empty after trim. Decision recorded under §6 below. |

All other columns are ignored on income rows. Rows with `type` other than `income` are skipped silently.

## 3. UX

### 3.1 Entry point

New **Bulk import** button in the Income tab, next to the existing add-income form.

### 3.2 Modal

Styled to match the existing scan-receipt dialog. Three states:

1. **Picker** — file input accepting `.csv`. Help line: *"Upload a Duitful CSV. Only the `income` rows will be added — everything else is ignored."*
2. **Preview** (after file pick + parse) —
   - `<N> income rows ready to add`
   - `<currency> <total> total across <M> months: 2026-04, 2026-05, …`
   - `<K> rows skipped` with a collapsible list: `Row 5: missing name`, `Row 9: invalid amount`, etc.
   - **Apply** button (disabled if N === 0). **Cancel** button.
3. **Done** — toast `Added <N> income entries`, modal closes, Income tab rerenders.

### 3.3 Error states (preview)

- File not selected, empty file, or `parseCSV()` produces zero rows → `"That file looks empty."` Apply disabled.
- Header missing the `type` column → `"This doesn't look like a Duitful CSV (no 'type' column)."` Apply disabled.
- All rows are non-income or invalid → preview shows `0 valid rows` with skip reasons. Apply disabled.

## 4. Data flow & persistence

1. User selects file → `FileReader` → text → `parseCSV()` (existing helper, `app/script.js:2660`).
2. New helper `parseIncomeRows(rows)` walks rows, returns `{ valid: IncomeEntry[], skipped: SkipNote[] }`.
3. Preview renders from that result.
4. On Apply: `state.income.push(...valid.map(r => ({ id: uid(), ...r })))`, then `save()` (existing — encrypts to localStorage), then `renderIncome()`.
5. Modal closes, toast appears.

No network calls. No new state-shape fields. No migrations.

## 6. Decisions recorded

Captured during the brainstorm so future readers don't have to re-derive them:

- **Aggregation:** rows are imported one-to-one as separate income lines. No summing by name+month. *(B in brainstorm)*
- **Currency:** no FX conversion at import. Values trusted as display currency. *(A in brainstorm)*
- **Format scope:** only Duitful's 17-column export shape is accepted. No simplified 3-column variant. *(i in brainstorm)*
- **Note handling:** `note` column on income rows is folded into the name as `"<name> — <note>"` so freelance gig context is preserved without changing the `state.income` schema. *(B in brainstorm — note-handling question)*
- **Behaviour vs existing destructive `Import CSV`:** distinct buttons, distinct intents. The existing one stays as backup-restore. The new one is additive bulk-add.

## 7. Out of scope / follow-ups

- Adding a `note` field to the `state.income` schema proper (the cleaner alternative to name-folding). Considered and rejected for this spec because it touches `toCSV`, `fromCSV`, the income edit form, and income list rendering. Could be revisited if more fields (currency, source category, etc.) accumulate demand.
- A simplified 3-column CSV format (`date,name,amount`) for non-Duitful sources. Trivial to add later by extending `parseIncomeRows` to detect a missing `type` column and treat all rows as income.
- A "merge whole CSV" mode that additively imports every row type, not just income. The §1 non-goals exclude this; it would replace the existing destructive importer's role, which is a separate decision.
