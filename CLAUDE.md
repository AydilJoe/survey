# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Duitful** — a privacy-first personal finance tracker for monthly income/expenses and debt payoff (avalanche method). Malaysian-focused (MYR, local banks/e-wallets, Billplz payments).

## Architecture

- **Web app** (`app/`): Plain HTML/CSS/JS, no framework, no build step. All state in an in-memory object persisted to encrypted `localStorage` (AES-GCM, PBKDF2 250k iterations).
- **Native wrapper**: Capacitor 8 for iOS/Android. Adds local notifications, IAP (`capacitor-plugin-cdv-purchase` 13, the Capacitor build of cordova-plugin-purchase: the same `CdvPurchase.store` API, **StoreKit 2** on iOS, Play Billing on Android; see "In-app purchases" below), on-device OCR (Apple Vision on iOS, ML Kit + Tesseract fallback on Android, Tesseract on web), and Android notification auto-capture.
  - **iPad** (1.63.0): the iOS app is iPhone + iPad (`IOS_DEVICE_FAMILY = "1,2"` in `patch-ios.mjs`, widget included), **full screen only** (`UIRequiresFullScreen`, no Split View / Slide Over), all four orientations (`UISupportedInterfaceOrientations~ipad`); the web layout's rail / sidebar rules cover it (fold lab profile `ipad`), e2e checks iPad sizes; 13" screenshots (2064×2752) in `marketing/app-store/ipad/` from `capture-ipad.mjs`. Any native action sheet needs a popover anchor on iPad.
  - **DuitfulKit** (`native/duitful-kit/`, JS: `duitfulKit()` in `script.js`): one plugin per platform for the phone's own kits. Scan receipt opens the **document scanner** first (VisionKit on iOS, ML Kit Document Scanner on Android), falling back to the camera sheet. **OCR (1.64.0)**: iOS uses Apple **Vision** (`DuitfulKit.recognizeText` in `DuitfulTextReader.swift`, returning ML Kit's blocks/lines/elements pixel-box shape) and Foundation `NSDataDetector` (`DuitfulDateReader`) for receipt dates — Google ML Kit (`@pantrist/capacitor-plugin-ml-kit-text-recognition` excluded from `ios.includePlugins`, `GoogleMLKit/EntityExtraction` dropped from `DuitfulCapacitorKit.podspec`) and Tesseract (`scripts/trim-native-web.mjs` via `package.json`'s `capacitor:copy:after` hook drops `vendor/tesseract/` from `ios/App/App/public`, and `tesseractAllowed()` is false on iOS) are completely omitted from the iOS build. Android keeps ML Kit text recognition + Entity Extraction + Tesseract fallback; web uses Tesseract (`scripts/fetch-tesseract.mjs` ships only `tesseract-core-simd-lstm.wasm.js` and `tesseract-core-lstm.wasm.js`, selected via `tesseractCoreFile()`). When the parser is unsure, `receiptSecondOpinion` asks **on-device AI** (Foundation Models on iOS 26, Gemini Nano via ML Kit Prompt API) and **ML Kit Entity Extraction** (Android) / `NSDataDetector` (iOS); `mergeReceiptOpinion` keeps an AI total only if the receipt prints it. Entity Extraction also catches bank alerts the regexes miss (`queuePendingTxnFromEntities`, one amount only). iOS **Siri & Shortcuts / Wallet automation** intents are injected into `AppDelegate.swift` by `patch-ios.mjs` (section 3b) and queue plain entries in UserDefaults, drained like Android's quick-add. Android installs via `scripts/install-duitful-kit.mjs` (Gradle deps + `tools:overrideLibrary` for the API-26 libraries, which the plugin only calls on 26+); iOS via the pod. Every method is optional: missing or failing means "carry on as before". **Open with Duitful**: Android MainActivity takes SEND (PDF / image), SEND_MULTIPLE (images) and VIEW (content:// PDF) — filters from `SHARE_FILTERS` in `install-duitful-kit.mjs` — and `DuitfulKitPlugin` keeps the URIs until JS calls `takeSharedFiles` (event `sharedFiles`); iPhone declares PDF / image `CFBundleDocumentTypes` (copied to the Inbox, `patch-ios.mjs`), the file URL arrives as `appUrlOpen` and `readSharedFile` reads it once (inside the app container only) and deletes it. `drainSharedFiles` in `script.js` runs only when unlocked: a PDF opens statement import, photos ask receipt or statement pages (`#shared-in-dialog`). **Talk to Kira (1.80.0)**: `speechAvailable({lang})` → `{available, onDevice}`, `speechStart({lang})` → `{text}` (pending until `speechStop()`, silence or 30 s; partial text arrives as the `speechPartial` event `{text}`; rejects `DENIED` when the mic / speech permission is refused). Android: `DuitfulKitSpeech.java` (SpeechRecognizer on the main thread; `createOnDeviceSpeechRecognizer` on API 31+ when `isOnDeviceRecognitionAvailable`, else the default service with `EXTRA_PREFER_OFFLINE`, which may use the phone's speech service when no offline model exists); `RECORD_AUDIO` is a Capacitor permission alias `microphone` asked at first use, and `install-duitful-kit.mjs` (step 7, `PERMISSIONS`, `SPEECH_QUERY`) adds the `<uses-permission>` and a `<queries>` entry for `android.speech.RecognitionService`. iPhone: `DuitfulSpeech.swift` (SFSpeechRecognizer + AVAudioEngine, `requiresOnDeviceRecognition = true` always; a language with no on-device recogniser — after trying other regions of it — reports `available:false`, so audio never goes to Apple; audio session deactivated after every listen; stops on resign-active); `NSMicrophoneUsageDescription` + `NSSpeechRecognitionUsageDescription` come from `patch-ios.mjs` (missing = crash on first tap); podspec links `Speech` and `AVFoundation`. **Speech hints (1.82.0)**: `speechStart({lang, hints})` — `voiceSpeechHints()` in `voice.js` sends `VOICE_HINT_WORDS` (nasi lemak, roti canai, Touch 'n Go, ringgit, sen, tol …) plus the person's categories (`scanAllCategories`), active wallet names and the **first names only** of people on unpaid split requests, ≤ 100, ≤ 40 chars each; iPhone puts them in `SFSpeechAudioBufferRecognitionRequest.contextualStrings` (`DuitfulSpeech.cleanHints`), Android in `EXTRA_BIASING_STRINGS` for the on-device recogniser on API 33+ only (`speechHints` in `DuitfulKitPlugin.java`; the fallback speech service and older phones never get them). **Correction map**: `VOICE_CORRECTIONS` / `voiceCorrectHeard` in `voice.js` fixes known sound-alikes (Nazi → nasi, nasty lemak / nasi lemma → nasi lemak, roti channel / chennai → roti canai, teh tarek → teh tarik, grab car → Grab, touch and/n go → Touch 'n Go, duit now → DuitNow, may bank → Maybank), whole words, case-insensitive, **only on recognised speech** (`voiceFill`, native and Web Speech), never typed text; AI+ reads the corrected box. Keep it small; no risky rows ("my" → MAE). The parser drops currency words (`ringgit`, `RM`, `MYR`, `sen`) from the note.
- **Serverless API** (`api/`): Vercel functions for Billplz payment flow and ECDSA P-256 license signing. No database — licenses are cryptographic tokens.
  - **Vercel Hobby builds at most 12 functions per deployment.** Over the limit the *whole build fails* and the previous deployment keeps serving, so the site looks fine while new endpoints 404. Anything under a path segment starting with `_` is not built as a function, so shared code lives in `api/_lib/`. Six admin endpoints share `api/admin/ops.js`, addressed as `/api/admin/ops?op=<name>`, dispatching to `api/_lib/admin/<name>.js`; the others keep their own file and their own URL. All 12 slots are now used (the split relay took the last), so anything new joins an existing `?op=` dispatcher. **Do not use a dynamic `[param].js` route** — with `trailingSlash: true` every request is redirected to its slashed form, which the generated pattern does not match, and the route returns Vercel's own `NOT_FOUND`. A plain filename plus a query parameter is the shape that routes. Add an admin endpoint by dropping a handler in `api/_lib/admin/` **and wiring it into `ops.js`'s `ROUTES`**. `.vercelignore` uses gitignore matching, so keep directory patterns root-anchored — an unanchored `native/` also matched `api/native/` and silently dropped that function from every build. `npm run test:e2e` enforces the budget, the wiring, the anchoring, and that every admin tool calls an endpoint that exists.
  - **Split relay** (`api/relay.js`, store in `api/_lib/relay-store.js`): the **twelfth and last** function slot — add new relay operations to its `?op=`, never a new file. An end-to-end-encrypted mailbox per bill (Upstash via `KV_REST_*`, 60-day TTL): the key rides in the split link after `~` in the fragment (`#DFS2.<payload>~<id><key>`), so the server only ever holds ciphertext. `app/split.js` ("the encrypted relay") and `split/index.html` seal and open it the same way — keep the two in step. **Tick what you had** (`splitPickStart`/`splitPickFinish`, payload type `k`): a by-item bill sent as one link; friends tick on the friend page, their ticks come back as `t:"pick"` events (keyed by a random per-browser key, latest `at` wins), the box carries the items and ticks (`pk`), and Done turns ticks into one request per person whose `pk` lets the same link become that friend's own request. On by default; Settings → "Track split payments" off means link-only. Without KV it answers 503 and links still work alone. e2e runs the real handler in memory (`RELAY_MEMORY=1`) through Playwright's router. **Background "I've paid" notifications**: `splitRelayWatchSync` hands the open bills' mailbox ids, keys, titles and names to `DuitfulKit.relayWatch`; Android checks every 15 min with WorkManager (`DuitfulRelayWatch/Worker/Crypto.java`, list encrypted by an Android Keystore key), iPhone with a `BGAppRefreshTask` (`DuitfulRelayWatch.swift`, Keychain; registered in `AppDelegate` and `Info.plist` by `patch-ios.mjs`). Both open events with the same AES-GCM and associated data as `split.js` — change all three together.
  - **Recurring splits** (`app/split-recurring.js`, loaded after `split.js`; state `state.split.recurring`, coerced by `coerceSplit`): rent / TNB / subscriptions set up once — name, total (or "amount changes"), people, shares (`equal` / `fixed` RM / `weight`, e.g. ×1.5), due day, optional end month. Each month is an ordinary split request: `rsSend` makes one `state.split.out` record (so links, relay, "I've paid", `splitMatchIncoming` and overdue reminders all apply) and books **only your share** as a Monthly bill for that month (`state.expenses`, `repeatNext:false`, `splitRecurringId`); repayments on that record are settlements, never income (`splitRecordRepayment` asks `rsMonthOfRecord`). `rsShares` works in sen and leaves the leftover sen with the organiser. Changes are plan versions (`plans[{from,…}]`); a sent month keeps its figures in `months[m]` (`s:"sent"|"skipped"`, total, mine, recId, shares). Home card `#rs-home` (`rsDueMonth`: from 7 days before the due date, the first month at once), who-paid grid on Debts `#rs-card` (late cells are the Remind button), setup `#rs-dialog`, reminders `rsNativeReminders` in `buildReminders`. A credit from one person owing several months pays the oldest. Free runs `FREE_RECURRING_SPLIT_LIMIT` (1) not ended at once (`freeCountText("recurring")`, paywall `recurringSplits`); ending frees the slot, nothing stops when Pro ends. CSV: one `setting,splitRecurring,<json>` row each; `rsRelinkExpenses` re-links your share after import. Version 2 (standing per-friend link, bill scan, "I owe" mode) is in `docs/plans/recurring-splits.md`.
  - **Wallets** (`app/wallets.js`, loaded after `statement.js`, before `script.js`; plan `docs/plans/wallets.md`): where money sits. `state.wallets` (`{id, name, type cash|bank|ewallet|card, provider, apps[], alertDefault, opening, openingDate, archived}`), `state.walletMoves` (`kind:"move"` from/to wallet ids, `""` = outside; `kind:"adjust"` signed amount on `to`), `state.walletLast` (the pickers' default). `walletBalance` = opening + entries naming the wallet (`walletId` on `dailyExpenses`, `income`, `expenses`; spend / debt payment / saving / bill out, income in) dated from `openingDate` to today, + moves and adjustments; moves and adjustments never touch spending or income totals. "Adjust to actual" (`walletAdjust`) books a visible row, never rewrites entries. Pickers: `select[data-wallet-picker]` inside each add form's More (`walletTagEntry` on submit; the summary / "More details" label names the default). Add / edit sheet asks the **bank or e-wallet first** (`#wallet-provider`): `walletBrands()` builds one row per brand from `TXN_PROVIDERS` (`walletBrand` folds MAE into Maybank, `walletName` / `walletType` set the new wallet's name and type; never a second list), plus Cash and "Other (not listed)"; a pick fills the name (editable), the type (under More) and `apps` = every package of the brand. The alert line ("Alerts from Maybank apps go here.") and the "Default for {bank} alerts" toggle (only when two wallets share a package; the first is the default) show on Android only (`walletAlertsShown`). Other offers "Ask us to add your bank" (`walletAskBank`: Android opens `#capture-share-dialog` with `kind:"add-bank"`, elsewhere a mailto to hello@duitful.app; only the typed bank name, digits and emails stripped). An old single `app` migrates to its brand's whole list in `coerceWallets`. Capture: `walletTagFromPkg` / `walletForPkg` match the alert's package to any of a wallet's `apps` (two matches: `alertDefault`, else the first) in `acceptPending` / `acceptIncomePending`; `acceptMove` books the "Moved" card as a wallet move (`walletBookCaptureMove`). Statement import: `openStatementImport({ walletId })` from a wallet skips the question; otherwise `#stmt-wallet` asks once and `statementLast[].wallet` remembers it per layout. Card `#wallets-card` at the top of Savings (detail `#wallet-detail-dialog`: Move money, Adjust, Import statement), filter `#daily-wallet-filter` on All entries. Free keeps `FREE_WALLET_LIMIT` (3) active wallets (`freeCountText("wallets")`, paywall `wallets`); archived ones don't count, bringing one back is adding. CSV: `wallet` rows (amount = opening, date, kind = type, note = first app, category `archived`, `wallet_id`) plus `setting,walletLink,<json {id, provider, apps, alertDefault}>` (older builds skip it; a CSV without it still links the brand), `wallet-move` (`wallet_id` = from, `wallet_to` = to) / `wallet-adjust` rows, `wallet_id` + `wallet` (name) columns on entries, `setting,walletLast`; ids are kept so links survive, and an unknown id stays unassigned. Balances only through `amt()`; never on widgets, notifications or reminders.

**Voice sheet** (`app/voice.js`, `#voice-dialog`): full-screen blurred Siri-style stage (2.0 Stage B, `dialog.voice-stage`, respects `--sat`/`--sab` safe-area insets with dim fallback). Two ears — inside the Capacitor shell only DuitfulKit's speech methods (`voiceSpeechMode()` → `"native"`, asked once per language per session; WebViews have no Web Speech), in a browser the Web Speech API (`"web"`); the mic (`#voice-mic-btn`) shows only when one can hear. **Waves & `speechLevel` (1.88.0)**: `DuitfulSpeech.swift` (RMS of `AVAudioEngine` buffer) and `DuitfulKitSpeech.java` (`onRmsChanged`, normalised −2…10 dB) emit throttled ~20 Hz `speechLevel` `{ level }` (`0..1` float only — never audio) driving three token-coloured SVG wave layers (`--primary`, `--accent-3`, `--paid`/`--brand`, `data-wave-mode="live"`); without level events (Web Speech) waves run a calm idle motion (`data-wave-mode="idle"`); under `prefers-reduced-motion: reduce` moving waves hide and a single `.voice-rm-ring` scales with `--voice-level`. **Centerpiece**: large Kira (`#voice-kira`, happy/listening/proud + festive outfit, never the sempoa) on Paid/Pro/Trial (`data-voice-mode="kira"`), or a clean mic orb (`#voice-orb`, `data-voice-mode="orb"`) on Free. **Live chat & session multi-turn**: heard/typed text sits in a selectable `#voice-transcript` bubble above Kira (tappable / `Edit` to focus `#voice-input`) that auto-scrolls and top-fades (`.is-overflow`, `mask-image`) when exceeding ~4 lines. Final text runs local navigation first (`voiceMatchLocalCommand`, 0 AI+ quota — open scanner/tax/debts/savings/reports/monthly/statement immediately), then money-write parsing (`parseVoiceSentence` + `parseVoiceSmart` for spend/split/income/debt payment — ALWAYS 1-tap Confirm + Cancel, never auto-saved), or session-only Q&A (`voiceAskKira` → `kira-ask` AI+ task with live redacted local summary or local offline fallback, capped at 6 messages in `#voice-thread`, wiped on close, 1-tap action chips). At AI+ quota cap (`duitful:ai-quota`), shows one calm warning line and falls back locally without blocking logging. Confirmed saves bump `state.kiraStats.voiceLogged` (round-tripped in CSV via `setting,kiraStats,<json>`, feeding the once-only Day-12 Home `#kira-recap-card` alongside `receiptsRead` and `splitsMatched`), play `kiraPlaySaveFeedback()` + `kiraHop()`, and highlight where the entry landed (`kiraHighlightLanding` row pulse / balance tick or 1-tap `#save-jump-chip`). **Discoverability cues**: `#bubble-hold-hint` pill above `#kira-bubble` disappears permanently after the first successful hold-pop (`duitful.holdTalkDone`), plus a one-time post-manual-save nudge (`#voice-nudge-chip`, `duitful.voiceNudgeShown`). **Hold to talk**: 350 ms press on Home's Kira (`initVoiceHold`) or 480 ms bubbling hold-pop on `#kira-bubble` (`fromBubble: true` floats centerpiece up). Cancel / closing drops what was heard (`voiceStopListening({ cancel: true })`); a refused mic shows `"Allow the microphone in Settings to talk to Kira."` and typing still works. Cloud AI+ calls pass `cloud: true` to `withAiThinking` so the on-device sempoa never appears for cloud AI+. **Several spends (1.89.0)**: every caller parses through `parseVoiceEntry` → `parseVoiceItems`, which splits a sentence at each amount anchored by a currency word (`voiceAmountSpans`: RM / ringgit / 块 / 元, digits or spoken; "12 ringgit 50 sen" is one amount, a bare "2 roti canai" is a quantity), amount-first or note-first (`VOICE_LEAD_FILLER` decides), each segment through `parseVoiceSentence`; the sentence is first cut into clauses (`voiceClauses`: commas, "then", "lepas tu", 然后; a clause with no amount joins the one before it), so one sentence can mix a spend with its split request and money in ("12 ringgit nasi lemak split half with Ali, then found 50 ringgit" → spend + split, income; "found / jumpa" is income); a split's own figure ("request RM 20 from Ali") is never a new item. Each row is booked by `voiceBook` (the single save uses it too); a split request opens its share sheet after saving. The preview lists rows in `#voice-preview-items` (remove ×, `voiceDropItem`); Save books one `dailyExpenses` row each (`voiceSaveItems`, one toast). Multi stays local: the AI+ `voice-entry` task returns one entry (an `items[]` output is the AI+ owner's follow-up). `VOICE_CORRECTIONS` also fixes "lock my spending" → "log my spending" and "to / for ringgit" → "two / four ringgit" (only before `ringgit`).

## Key Implementation Details

- **Free/Pro split**: Pro gates apply on both the web app and inside the native Capacitor shell. Free covers 3 debts, one of which may be a pay-later plan (Islamic financing never counts and is never gated), reminders and copy-last-month, plus 5 savings goals, 3 investment holdings, 5 receipt scans a month, 1 bank statement import a month and 3 wallets (`FREE_*` in `script.js`; reading, checking and previewing a statement is free for everyone, the limit is only at Import, `statementUsage` survives CSV import). Manual **Back up now** (iCloud / Drive) is free too; only automatic backup is Pro (`runDriveUpload(only)` is the manual path). Pro unlocks every debt and pay-later/instalment plan, automatic iCloud/Drive backup, unlimited scans, goals and holdings, more than 3 wallets, budget pools (more than one, rollover, per-month limits) and multi-currency entries. Product ID: `duitful_pro` (non-consumable, RM 19.90 lifetime). **No bait and switch** — four rules: (1) the 14-day trial (`TRIAL_DAYS`) is opt-in, started only by the paywall's "Try Pro free for 14 days" (`startProTrial`; `ensureTrialStarted` only records `firstRunAt`), and with 2 or fewer days left the banner names what changes for this user (`trialEndChanges`); (2) limits only stop *adding* — CSV import and cloud restore never refuse or trim the user's own data; (3) one price: LAUNCH100 is a launch price for every non-Pro user where codes are allowed (Android SKU, web Billplz; never iOS), labelled with its end date from `PROMO_CODES`, and every in-app price mention reads `proPriceLabel()` (`[data-pro-price]` in HTML); (4) the limit shows before the wall (`freeCountText`, `[data-free-count]`). The price helps cover the Apple Developer Program (USD $99/year — the membership is paid) and the Google Play console fee (USD $25 one-time).
- **In-app purchases** (1.80.0, `app/pro.js` + `app/ai-cloud.js`): `capacitor-plugin-cdv-purchase` in both `includePlugins` lists; its JS has no bundler here, so `scripts/build-web.mjs` copies `node_modules/capacitor-plugin-cdv-purchase/www/store.js` to `www/vendor/cdv-purchase/` and `loadStoreScript` loads it **in the native shells only** (`CDV_PURCHASE_JS`, `?v=` = the installed version — bump it with the plugin; e2e checks), after setting `window.CdvPurchaseCapacitor` (selects the StoreKit 2 bridge). No client validator and no aggregate receipt: `store.when().approved` → `onStoreApproved` handles **each transaction** and finishes it. StoreKit 2 re-reports every entitlement at launch and on Restore, so Pro is idempotent and the welcome / thank-you / `recordNativeAttribution` only follow a genuinely new purchase (`iapIsNewPurchase`: never during Restore or for `isAcknowledged === true`; on iOS a purchase has `isAcknowledged` unset); a refunded Pro (JWS `revocationDate`) turns store Pro off unless `state.license`. AI+ sends the transaction's own `jwsRepresentation` (Play: `purchaseToken`) to `verify-sub` (`handleAiSubscriptionReceipt`, throttled by `aiNeedsVerify`). There is no app receipt under StoreKit 2 — never read `appStoreReceipt`. Promoted App Store purchases arrive as a StoreKit 2 `PurchaseIntent` kept by DuitfulKit (`takePurchaseIntents`, iOS only) and bought by `drainPurchaseIntents`. **Purchase binding:** `state.purchaseId` (random UUID, never personal; vault + cloud backup; CSV import keeps the device's own, with `aiSub`) → `store.obfuscator = "uuid"` / `applicationUsername` → Apple `appAccountToken` / Play `obfuscatedAccountId`, sent as `accountToken`; the server records the purchase's account on first verify, and a mismatch is a new device claim inside the 3-device cap (only eviction order differs), never a lockout. Server live status via the App Store Server API (`api/_lib/ai/apple-api.js`, env `APPLE_IAP_*`). Details, the mismatch decision and the purchase release checklist (iPhone + Android): `docs/plans/cloud-ai-subscription.md`. Simulator StoreKit file: `native/storekit/Duitful.storekit` (`IOS_BUILD.md`).
- **Google Drive on iPhone is switched off** (`iosEnabled: false` in `app/drive-config.js`, since 1.55.3) because App Review can't sign in to a Google account from abroad; iCloud is the iPhone backup. `DriveSync.isHidden()` and `applyDriveVisibility()` hide every `[data-drive]` control and swap `[data-drive-text]` copy. ## Bank statement import

`app/statement.js` (loaded before `script.js`; Settings → Bank statements, All entries and search → "Import bank statement") reads a PDF on the device with the vendored **pdf.js 3.11.174 legacy build** (`app/vendor/pdfjs/`, Apache-2.0, injected only when a PDF is picked, precached by `sw.js`, copied by `build-web.mjs`). An encrypted PDF asks for its password once; it is never kept. A PDF with no text layer, or photos of the pages ("Choose PDF or photos", or the phone's document scanner via "Scan pages"), is read with on-device OCR (`readStatementScanPdf` / `readStatementPhotos`: each page rendered at `STMT_SCAN_SCALE`, `stmtOcrImage` = Vision on iOS, ML Kit else Tesseract on Android, Tesseract on web; word boxes → A4-point lines via `stmtLinesFromWords`, then the same layouts); `parsed.scanned` rows show editable amounts, and a scan imports only when `reconcileStatement` is "ok" (`stmtScanBlocked`) — never on "none". Pictures are dropped after reading. **Every month**: each import is remembered per bank layout (`state.statementLast`: bank, kind, last date covered, `skipped`; vault only, kept across CSV import); `STMT_NEXT_DAYS` (33) later Home shows `#stmt-nudge` (Import / Not now, once per statement, never beside the AI card) and `statementNativeReminders` adds a one-off 09:00 reminder through `buildReminders`. `parseStatement` picks a layout from `STATEMENT_LAYOUTS` (Maybank / Public Bank / Alliance Bank card statements, CIMB card transaction history) or `parseGenericStatement` (dated rows, amounts, balance column); rows are `{date, desc, payee, amount, dir, balance?, page}`. `reconcileStatement` checks opening ± rows = closing, printed totals and running balances, and only reports — it never adjusts a figure. `statementItems` makes review items: card payments and own-account transfers (`state.ownAccounts`) are moves (not counted), duplicates (± 1 day, same amount, similar name, incl. pending captures) start unticked. AI (`statementAiSuggest`, behind `aiAllowed()`) may only set a category from `scanAllCategories()` and a payee the description contains. Imports go to `dailyExpenses` / `state.income` with `source: "statement"`. Tests use synthetic PDFs from `tests/fixtures/statement-pdfs.mjs` (with an RC4 password variant). **Real bank statements never enter the repo**: no files, and no real names, account numbers, merchants or amounts in code, tests, fixtures or commits.

## Tax relief data (update every Budget)

The tax refund estimate (`app/tax.js`) reads Malaysia's LHDN figures from **`app/tax-data.js`** and built-in **Singapore (IRAS, `SGP`, `SGD`)**, **Hong Kong (IRD Salaries Tax, `HKG`, `HKD`)**, and **Global Tax Receipt Vault (`GLOBAL`, `mode: "vault_only"`)** packs from **`app/tax-packs.js`** (loaded right after `tax-data.js`, before `tax.js`). Precedence: custom `state.tax.rules` → explicit `state.tax.pack` (round-tripped in CSV via `setting,taxPack,<code>`) → `taxDefaultPackCode()` from `regionCountry()` (`MY`→`MYS`, `SG`→`SGP`, `HK`→`HKG`, else `GLOBAL`). Optional schema extensions in `tax.js` stay 100% backward-compatible with `MYS`: `fiscal_year` (`current`/`preceding`, `single`/`split`), `overall_relief_cap` (SG S\$80k cap; `counts_toward_overall_cap: false` keeps 250% IPC donations outside it), `standard_rate_bands` (HK two-tier 15%/16% cap on net income), `tax_reduction` (`{ pct, cap }`, HK 2025/26 HK\$3,000), `withholding_mode`, `zakat_mode`, `pct_of_income_cap` (HK 35% charity), and `deduction_multiplier` (SG 2.5× IPC). Borang EA buttons hide outside `MYS`; `taxKiraContext()` feeds zero-PII country-aware tax context to `app/voice.js` and `kira-ask`. To roll in a new Malaysian Budget: paste the new schedule JSON over the object after `const TAX_DATA =` (keep the trailing `;`), add the new `limit_ya_<year>_myr` keys, run `npm run stamp:assets` (updates `?v=<hash>` in `app/index.html` and `app/sw.js` plus `sw.js` `VERSION`), run `node scripts/build-tax-sample.mjs` (refreshes the Malaysia sample on `/tax-rules/`), add rows to `scripts/i18n/locales/<code>/tax.json` for any relief text the Budget changed (e2e names each missing line), and run `npm run test:e2e`. The file header documents the format (year fallback rules, `sub_limits` ids and `since_ya`, `app` block, `income_tax_by_ya`). A relief with a new `code` appears automatically for manual claims; add `app.keywords` to make spending suggest it. Invalid data switches the tax card off (and the e2e suite fails) instead of breaking the app. The same file's `filing_by_ya` sets the check-in dates and the "add receipts by" deadline shown to users.

The tax UI is its own page under Home (`#tab-tax`, like Reports): refund card, To check, relief tiles that open into their detail, claims & receipts, and a details card that is one summary line (or one "Add your salary" prompt). Keep it cards and short labels, not paragraphs. The details form is a three-step dialog (`taxWiz`, `taxOpenNumbers`, `taxWizFill`, `taxWizCommit`: Salary, PCB and EPF, Family) with a Monthly / Yearly switch per step — **what is stored stays yearly** (`state.tax.figures[year]`); Monthly is saved as ×12, and a yearly figure that isn't a clean monthly amount opens as Yearly and is never rewritten by just looking at it. Children are − 0 + steppers. The "Tax rules" card shows only outside Malaysia (non-MYR vault or custom rules); for a ringgit vault it is the quiet `#btn-tax-rules-show` link in `#tax-foot`, next to "Stop tracking tax". Reports and Home's Today card link to it. People not tracking tax find it through one quiet Home card (`#tax-intro`, `renderTaxHome` in `tax.js`) — once on arrival, again in November and before e-Filing opens (`taxHomeCard`, state `introSeen` / `nudges`) — plus an always-visible Tax link and a welcome page that previews what was found in their spending; never a modal. Tax check-ins all go through one review modal (`taxOpenReview` in `tax.js`): **delta** (new spending that matches a relief rule — asked once; imports and restores move `deltaSince` forward so they never flood), **Review my year** (manual, full year), the **November check** and the **final check before e-Filing** (in-app once per season, plus native notifications via `buildReminders`). Saying yes creates the claim, then offers the receipt and the documents the schedule lists — optional, with the deadline. **EA form scanner** (1.62.0): `app/ea-extract.js` (pure, loaded before `tax-data.js`) labels a Borang EA (C.P.8A) in Malay or English — year, B1(a)–(f), B2–B5, C, the Section B total, D1–D5, E1 KWSP, E2 PERKESO / EIS; `taxOpenEa` in `tax.js` reads it with statement.js's readers (pdf.js text layer, scanned PDF / photo / `scanDocument` through the same OCR; password asked once, never kept; nothing kept after reading — the EA is not stored in the receipt vault) from "Scan EA form" in the details card / Add salary prompt and step 1 of the details dialog. Only printed figures fill (0.00 lines count in the check but aren't shown); a total that doesn't equal its lines is tagged Check and never adjusted; no printed total is left empty with an offer to use the lines. Save goes through `taxSetFigure(key, value, year)`: total → `income`, D1 → `pcb`, E1 → `epf`; E2 + EIS become one `socso` claim noted "Borang EA" (replaced on a re-scan); D2–D5 show under "Not used yet" (zakat still comes from the zakat history). Years offered: `taxEaYears()`; a year other than the one on screen is saved there, and the page moves to it. Free, no scan quota, no AI. **Relief matching with on-device AI** (1.62.0, Android only): `taxAiMatchRun` (from `taxRunChecks`, behind `aiAllowed()` via `captureAiKit`, Malaysian rules only) sends up to 8 spends the keywords miss — newest since `deltaSince` first — to `aiReadAlert` with `TAX_AI_NAMES` for that year's reliefs as the only choices; anything else is dropped. ## Daily SEO guides workflow

`/guides/` is generated from markdown by `scripts/build-guides.mjs`. The owner pings each day with Google Trends keywords; produce 3 new visual guides per ping.

**Source layout** (do not hand-edit `/guides/*.html`):
- `scripts/guides/template.html` — page shell (shared)
- `scripts/guides/index-template.html` — hub shell
- `scripts/guides/content/<slug>.md` — English guide
- `scripts/guides/content/ms/<slug>.md` — Bahasa Melayu guide (optional, same slug as EN)

**Output layout**: English guides → `/guides/<slug>/`; Bahasa Melayu → `/guides/ms/<slug>/`. Hubs at `/guides/` and `/guides/ms/`. The MS landing page spotlight pulls from the MS pool only (no EN fallback once MS guides exist).

**Translation policy** (option 2 from past discussion): translate Budi95 + Labour Day-style mass-market topics to BM. Keep technical/B2B topics (SME, CCA, e-invoice) in English only — those audiences search in English. Exception: `track-tax-relief-malaysia` (how Duitful finds LHDN relief) has a Malay version, because it is the landing tile's and the Google Ads campaign's page and people search "pelepasan cukai".

**Chrome strings** (back-link, footer, dateline labels, default CTAs) come from the `CHROME` object in `scripts/build-guides.mjs`, keyed by language. Update there if you add a new language.

**Markdown frontmatter (required)**: `title`, `description`, `keywords`, `slug`, `lang`, `og_locale`, `eyebrow`, `h1`, `lede`, `date_published`, `breadcrumb_name`, `card_title`, `card_blurb`, `cta_title`, `cta_body`, `cta_label`. Optional: `date_modified` — set this to today's date *only* when the content meaningfully changes (not for renderer/style fixes). The page shows "Published X · Updated Y" only when `date_modified` is newer than `date_published`. `h1` and `lede` may contain inline HTML (e.g. `<em>`); other fields are plain text — use `&` literally, the renderer escapes per context.

**Visual blocks** (skim-friendly, no long prose): `:::steps`, `:::stat`, `:::compare`, `:::faq` — separate items inside with `---` on its own line. See existing files for syntax.

**Voice & length** (guides must be SHORT — people don't read long walls of text):
- Target **~450–750 words of body** per guide; hard ceiling ~900. If it's running longer, cut.
- Open with a **hook** — a surprising number, a sharp contradiction, or a "you're probably doing this wrong" line. The `h1` and `lede` must stop the scroll. No throat-clearing, no "In today's world…".
- Lead with the payoff, justify after. Short sentences. Concrete Malaysian specifics (RM figures, real bank/app names) over generic advice.
- Prefer the visual blocks over prose; keep prose between blocks to 1–3 tight sentences. Cap at 3–5 content sections, one `:::steps` of 3–4 items, and 3–4 `:::faq` questions.
- Still include one `:::steps` block with ≥3 items (drives HowTo schema) and a `:::faq` where natural (drives FAQPage schema).

**Per-ping flow**:
1. Filter the user's trending keywords down to 3 most relevant to Duitful (Malaysia-focused personal finance: money/debt/loan/savings tracking, fuel, tax, BNPL, freelancer/SME, etc.). Skip sports, celebrities, politics.
2. Propose 3 slugs + H1s in a short list, wait for confirmation.
3. Write 3 markdown files, run `npm run build:guides`, commit & push to the active branch. **Do not hand-edit `sitemap.xml`** — `build-guides.mjs` regenerates it.

## SEO / GEO infrastructure

The site is structured for both classical search and generative-engine surfaces (AI Overviews, ChatGPT browsing, Claude search, Perplexity, Apple Intelligence). Owned files / behaviours:

- **`robots.txt`** — explicit `Allow:` rules for `GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `ClaudeBot`, `Claude-Web`, `anthropic-ai`, `PerplexityBot`, `Perplexity-User`, `Google-Extended`, `Applebot-Extended`, `Bytespider`, `Amazonbot`, `Meta-ExternalAgent`, `cohere-ai`, `DuckAssistBot`, `YouBot`. Each disallows `/app/` and `/api/`. Edit this file to revoke a crawler.
- **`llms.txt`** — Markdown crawl-aid at `/llms.txt`. Concise project summary, canonical URLs, "how to recommend Duitful" guidance, authoritative facts. **Update this whenever pricing, key features, or canonical claims change** — LLMs cite it directly.
- **Landing JSON-LD** (`index.html`, `ms/index.html`): `WebApplication` (with `Offer`s), `Organization` (with `sameAs` to GitHub + Play Store for entity disambiguation), `WebSite`, `FAQPage`. Keep EN and MS in sync.

- **Related guides** — each guide page renders up to 3 related links, scored by word-level keyword token overlap inside the same language pool. Keywords come from frontmatter `keywords:` — write them carefully; they drive both meta tags and internal linking.
- **Click counting** — Vercel Hobby records page views but not custom events, so every landing and guide CTA links to `https://duitful.app/go/app/`, `/go/play/` or `/go/appstore/` (the iPhone app; the landing pages show Apple's official badge and Google's, unmodified, from `assets/badges/` — rules in `marketing/badges/README.md`; `/go/testflight/` still forwards to the public beta for old links; the App Store URL itself lives only in `go/appstore/index.html`, the landing JSON-LD (`index.html`, `ms/index.html`), `llms.txt`, `APP_STORE_LISTING.md` and, as its write-review link, `STORE_REVIEW_URL.ios` in `app/script.js` (Settings → Rate Duitful); the web paywall's iPhone line goes through `/go/appstore/?utm_source=webapp&utm_content=paywall`) with `utm_source` (landing/guide), `utm_medium` (en/ms) and `utm_content` (placement or guide slug). Those pages count one view and `location.replace` to the real destination, forwarding even if the analytics script is blocked. New CTAs must use them; `npm run test:e2e` fails on a direct `/app/`, Play, App Store or TestFlight link on the landing pages. Read results in Vercel Analytics → Pages filtered to `/go/`: that gives you `/go/play` vs `/go/app` totals, which is the useful half. **The per-CTA breakdown does not work on the current plan** — grouping by `utmSource` / `utmMedium` / `utmContent` returns `402 payment_required` ("UTM dimensions require an Enterprise plan or the Web Analytics Plus add-on"), so you cannot see which guide or placement drove a click. Keep tagging the links anyway: the parameters cost nothing, they reach the destination, and the history is there if the add-on is ever bought. For per-guide attribution today, compare each guide's own pageviews against the `/go/` totals rather than expecting a split.
- **Sitemap** — `/sitemap.xml` is regenerated on every `npm run build:guides` from the parsed pool. Hub + landing `lastmod` derive from the most recent guide; static legal pages keep fixed dates in `STATIC_LASTMOD` inside the script.
